## 決定事項
- 5 時間枠が JSON に無いときは何も出さない（従来どおり JSON の有無で決める）。理由: JSON にあるかどうかが唯一の確かな情報。Ultra でも認証前の新しいアカウントには一時的に 5h があり、プラン名からは決められない。ステートレスでは「Ultra」と「Pro/Max の放置後リセット」を区別できない。
- Fable の週制限は、ステータスラインの JSON に来たら表示する（汎用の枠表示で対応）。現時点では JSON に含まれないので表示されない。理由: 通信なし・認証情報に触れない方針を守るため。
- 新フィールドはすべて環境変数でオフにできる形で既定オン。pr.url は正規表現 `^https?://[A-Za-z0-9._~:/?#@!$&+,;=%-]+$` に合うときだけリンク化（OSC 8 シーケンスへの注入対策）。
- gh フォールバックで番号を補ったときは、JSON 側の pr.url / pr.kind を使わない（番号の無い pr オブジェクトの残りを別の PR に付けないため）。

## 捨てた選択肢と理由
- Fable 週制限を非公開の /api/oauth/usage から取る（キーチェーンの OAuth トークンを読んで 5 分キャッシュ）: 非公開 API で予告なく壊れうる、トークンをシェルスクリプトで扱う、通信が発生する、usage エンドポイントはレート制限がある。ユーザーが不採用を選んだ。
- 5h が無いとき「5h —」と明示: Ultra と Pro/Max のリセット直後が同じ表示になり意味が曖昧。
- ~/.claude.json の oauthAccount.planDisplayName でプランを判定して出し分け: 非公開の内部ファイルに依存し、認証前の Ultra は 5h があるのでプラン名では決まらない。
- 最後に見た five_hour.resets_at をキャッシュしてリセットか否かを推定: ヒューリスティックで、プラン変更後に古い状態が残る。

## ハマりどころ
- `IFS=$'\t' read` はタブが IFS の空白文字扱いなので、連続タブ（空フィールド）が潰れて列がずれる。空になりうる列（resets_at）を最後に置いて回避。
- jq は出力を逐次流すため、途中でエラーになるとそれより前のフィールドは残り、後ろだけ空になる。耐性テストは失敗箇所より後ろのフィールド（rate_limits の後ろの pr.number）で検査しないと旧版でも通ってしまう。
- テストの期待値 '$314.12/$500' が ShellCheck SC2016 に引っかかり CI が落ちた。shellcheck は手元に無く CI でしか検出できない。"\$314.12/\$500" に修正。
- この環境の grep は ugrep のエイリアスで、`.{0,300}` のような大きな繰り返しはエラーになる。バイナリ文字列の検索は python で行った。
- （未修正の既存の癖）JSON の cwd が存在しないディレクトリだと git はスクリプト自身のカレントディレクトリにフォールバックする。README の「スクリプト自身のカレントディレクトリには依存しません」と厳密には食い違う。
